# Sales-CS 复盘与升级（Review）

扫描客户反馈，结合用户意见产出升级建议，用户确认后落地到客服话术与手册文档。本 workflow 在 EvoFlow 单 agent 架构下由 agent 直接执行，无独立对外 crew。

**依赖**：`sales-cs-review`（反馈扫描）。文档修改由 agent 直接编辑。

---

## 前置条件

- `EVOFLOW_MEDIA_WS` 已 export，且 `$EVOFLOW_MEDIA_WS/feedback/` 存在（不存在说明尚无客户反馈，可直接反馈用户）。

## 执行流程

### Step 1 · 扫描反馈

```bash
sales-cs-review
# 或限定时间窗：
sales-cs-review --since 2026-06-01
```

输出 JSON：反馈条目数、按文件分布、高频关键词（投诉/退款/价格/试用/开票/人工…）。输出字段细节见 `sales-cs-review` 工具说明。

### Step 2 · 结合用户意见生成升级建议

读反馈摘要 + 用户本轮诉求（用户临时发起时）或定期巡检发现（定期复盘时），提出具体建议，**不直接动手**，先呈现给用户确认。建议对象（均在 `$EVOFLOW_MEDIA_WS/` 下）：

- **客服手册 / FAQ**：补/改 FAQ、价格政策、开票流程（业务知识文档）
- **话术**：调整各场景应对策略（业务知识文档中的话术段）
- **业务知识正文**：`business_knowledge.md` 的事实与政策纠偏

> ⚠️ 源流程中针对独立 crew 的「调整对外称呼 / 增减可用技能 / 角色边界文件」段落在 EvoFlow 单 agent 架构下不适用——客户资料库与业务知识已按 EVOFLOW_MEDIA_WS 约定共享，无需 crew 化。

呈现形式：

```
建议改动：
1. 业务知识「常见问题 FAQ」补一条：退款流程 -> 引导填反馈问卷
2. 话术段：把"先讲适合解决什么问题"改为"先问客户场景再匹配"
确认后我直接改对应文档。
```

### Step 3 · 用户确认后落地

用户确认后，agent **直接编辑** `$EVOFLOW_MEDIA_WS/` 下的对应文档（业务知识 / 话术 / 手册）：

- 改完报平安：列出改了哪些文件、改了什么
- feedback/ 历史记录只读，不改
- 若涉及渠道 / 密钥配置变更（`AWADA_*`），指引改 `.env.xiaobei-keys`，不在本 workflow 内操作

---

## 调整边界

| 类别 | 范围 |
|------|------|
| **可改** | `$EVOFLOW_MEDIA_WS/` 下的业务知识、话术、客服手册文档 |
| **不改** | `$EVOFLOW_MEDIA_WS/feedback/` 历史记录（只读，用于复盘） |
| **转出** | 渠道 / `AWADA_*` 密钥配置 -> `.env.xiaobei-keys`（人工确认）；客户资料状态 -> `customer-db` |

## Pitfalls

- **没确认就改**：必须先呈现建议给用户确认，再落地。话术面向外部客户，误改影响真实对话。
- **把一次性问题当系统性问题**：单条负面反馈先核对原始对话再决定是否升级话术；多次出现的同类关键词才作为手册/话术修改依据。
- **业务知识双写**：业务知识只在 `$EVOFLOW_MEDIA_WS/` 单点维护；其他技能（expert-bd/expert-ir 等）也读它，改完注意告知影响面。
